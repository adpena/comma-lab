### F1 — MEDIUM — the published sign-determinacy margin divides by the wrong denominator

**Claim.** `p0_1111_ck1_restage_20260819.md:166`: *"The net is 18.0× the receipt's own report-8dp
error bound, so the sign is determinate by a stated margin."*

**Why it is wrong.** The net (−5.994113e-05) is a **difference between two rows**, each of whose
components is independently rounded to 8 decimal places. Their error bounds add. Dividing by one
row's bound understates the uncertainty by exactly the other row's contribution.

Measured:

| quantity | value |
|---|---|
| gen4 own bound | 3.336608391523776e-06 (receipt) |
| keep01 own bound | 3.345782440506067e-06 (its verdict memo) |
| seg delta bound (100 × 2 × 0.5e-8) | 1.000000e-06 |
| pose delta bound (both directions) | 5.681469e-06 |
| **bound on the NET** | **6.681469e-06** |
| claimed margin (net / gen4 bound) | 17.96× → "18.0×" |
| **correct margin (net / delta bound)** | **8.97×** |
| overstatement | **exactly 2.00×** |

**The conclusion survives** — 8.97× still makes the sign determinate. The *stated margin* does
not. This matters because this repository has a live discipline about exactly this number (the
`#1032` cure, "DIVIDE BY THE BOUND"), and the discipline is being applied with a single-row
denominator to a two-row delta.

**Class, not instance.** The same construction appears elsewhere: `ddm_keep01_ninth_pointer_move_verdict_20260818.md`
states *"the net is 164.9× the bound"* for a delta (true value ≈ 82×), and the CLAUDE.md memory
line records `sa3 net=16.1× it`. Every net-versus-prior-row margin in this campaign that divides
by one row's bound is overstated by roughly 2×.

**Evidence:** `.omx/research/p0_1111_ck1_restage_20260819.md:166` ·
`gen4_receipts/MODAL_REMOTE_RESULT.json` · `.omx/research/ddm_keep01_ninth_pointer_move_verdict_20260818.md:1,18-30`

**What MAIN must do.** Correct the memo to 8.97× with the two-row bound shown. Then run the
population query for the class — every `N× the bound` claim attached to a *delta* rather than to
a single row's own score — and fix the denominator wherever it appears, including the CLAUDE.md
memory line. Consider publishing the delta bound as a field beside the net, since the packet
already publishes deltas.

## 4. Assumption-challenge axis

**The shared assumption this packet rests on:** *the archive decodes identically in the contest
container as it did on our T4 worker, so a score measured on our worker is the score the contest
will compute.*

**Does violating it change the verdict? Yes — and the packet's own receipts show the violation is
not hypothetical.** Three measured facts, all from artifacts under review:

1. **Same bytes, different runtime → 79.40 instead of 0.157** (F6). A 505× swing. The archive does
   not determine the score; the (archive, runtime) pair does.
2. **Same bytes, same runtime, different microarchitecture → d_pose moves 19.08×** (F3). Our own
   advisory run is the counter-example. Under the current compensation design the pose leg is a
   near-cancelled residual, so it is *structurally* the most environment-sensitive quantity in the
   score. It is also the leg we most recently bought.
3. **Same bytes, different image → possible total failure** (F2). If the contest image lacks
   Brotli 1.2.0 and has no egress, inflate exits 69. That branch has never run.

**What this means for the packet.** The assumption is load-bearing and only *partly* defended. It
is well defended on the integer path: the token decode is device-exact, parse-back returns PASS at
`max_abs_code_deviation = 0`, and the tree shas pin the receiver. It is **undefended on the float
path and on the environment path**, and those are exactly where F2 and F3 live. The right response
is not to weaken the score claim — the T4 row is real and correctly labelled — but to state the
sensitivity explicitly, so a judge whose container differs knows which number to expect to move
and by roughly how much. The packet currently states the caveat qualitatively (README:163-166,
README:30) and has the quantitative evidence sitting unpublished in its own receipt folder.

**A second, quieter assumption worth naming:** *that a margin computed against one row's
quantization bound tells you whether a two-row delta's sign is real.* F1 shows that one is simply
false, and it is false by a clean factor of two everywhere it is used.

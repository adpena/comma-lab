## Answer First

The JD1 endpoint should decide a narrow question: whether joint descent has become a real pose actuator on the live task-space witness while preserving the already-earned seg state. It should not decide archive shippability by itself.

The next action after JD1 is conditional:

| JD1 endpoint predicate | Decision | Next fire order |
|---|---|---|
| Seg held at or below the calibrated hold floor neighborhood and pose term falls materially | QUEUED-WITH-FIRE-ORDER | byte-close the exact endpoint first, then apply the smallest terminal pose/rate compose gate before any vehicle redesign |
| Pose improves but seg erodes | QUEUED-WITH-FIRE-ORDER | run a short seg-recovery terminality check from the JD1 endpoint; if recovery fails, increase the seg-hold controller, not the model |
| Seg holds and pose is flat | QUEUED-WITH-FIRE-ORDER | fire the JB1 derived-Jacobian basis race at the boundary; the failure mode is likely basis/gradient alignment, not absence of pose bytes |
| Seg and pose both degrade | FOLDED for JD1-v2 promotion | classify as controller/formulation failure; do not byte-close or route downstream until the seg-hold bug is explained |

The strongest current route is not another broad witness training run. It is:

1. consume JD1 endpoint telemetry,
2. decide joint-descent physics,
3. if alive, byte-close the endpoint,
4. compose only the terminal/rate action that clears the current byte ceiling,
5. if not alive, pivot to the JB1 derived-basis race and the task-description archive corridor.

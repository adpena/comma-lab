## Typed frontier contract

Implement immutable/typed records (dataclasses or equivalent) for:

1. candidate custody;
2. per-level attribution;
3. one tolerance verdict;
4. U3 receiver-tuple preflight;
5. aggregate receipt.

The representation-level vocabulary is exactly:

```text
chart, object, event, exception, pixel
```

Each candidate must state bytes and miss-mass bought at every used level.  A
level may be absent or zero, but an unclassified positive byte count is a hard
refusal.  Pixel is not forbidden; it is simply attributed honestly.

A row is `MEASURED_FRONTIER_POINT` only if all of these are true and directly
custodied in the candidate receipt:

- target tolerance is one of the four exact targets;
- exact candidate bytes exist and their file SHA-256 matches;
- `receiver_closed=true`;
- exact parse-back/double-decode identity passed;
- full n600 hard-score custody exists;
- evidence is canonical `[contest-CPU]` or `[contest-CUDA]`; local advisory
  receipts are status inputs only and cannot create a frontier point;
- `d_seg`, `d_pose`, and counted archive bytes are measured on the same
  realized stream/archive;
- `d_seg <= target`;
- evidence axis is explicit and is not promoted beyond its source axis;
- no input identifier or hash is quarantined;
- per-level bytes sum exactly to the candidate's counted payload bytes, with
  separately stated archive-container overhead; generic runtime code is
  hash-bound but free and `runtime_overhead_bytes` must be exactly zero;
- source/runtime/evaluator/config/seed/GT hashes and exact argv are present.
- the actually executed evaluator script and canonical exact-eval command are
  cross-bound to the hash-checked current `upstream/evaluate.py`, not an unused
  sidecar token in argv.
- the runtime filesystem tree and every scored raw-output manifest entry are
  rehashed from current bytes, and the official output aggregate is rederived;
- a terminal external execution receipt is hash-bound to the archive, runtime,
  evaluator, argv, hardware, and output aggregate. Local receipt JSON is not
  execution proof: positive admission remains fail-closed until a live
  Modal/GitHub provider reconciliation verifier is implemented.

Anything else becomes a typed `BLOCKED_*` or `NO_FEASIBLE_CANDIDATE` row with
the narrowest `verdict_scope`.  Missing keys must not silently coerce to false
or zero.  Among passing candidates, choose the least counted bytes at each

## CLI and resumability

The CLI accepts explicit receipt/candidate paths; no broad filesystem guessing
may create authority.  It may offer a narrowly scoped discovery mode that
records every matched path and still validates hashes.  Required modes:

- `compile`: validate candidates and write the canonical receipt atomically;
- `validate`: rederive a receipt and fail nonzero on any mismatch;
- `preflight-u3`: emit the U3 predicate table and fail nonzero while blocked.

Bulk output defaults under
`/Volumes/VertigoDataTier/pact/evidence/einstein_kolmogorov_20260721/`; require
the SSD path and a free-space preflight.  Small committed summaries may be
written under `.omx/research/` only when explicitly requested.  Writes are
atomic.  A completed compile receipt is the resume checkpoint: identical
inputs validate/reuse it; changed inputs require a new output, never overwrite
an incompatible checkpoint.

The pointer score is not compiled as a literal. `compile` hash-binds and
reparses the unique contest-CPU row in `reports/latest.md`; receipt validation
repeats that parse so pointer drift fails closed. Input count/bytes are bounded
and SSD reserve scales with total metadata size.

Do not load full-P dense arrays.  Read only receipt metadata and stream large
JSON incrementally or extract bounded fields.

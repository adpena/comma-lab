## 3. Exact-D geometry: ideal lattice versus actual receiver fiber

### 3.1 The correct object

Let `R_pose` be the exact implemented map from two uint8 camera frames to the six-channel PoseNet
input, including resize, float arithmetic, and RGB-to-YUV conversion. Around a base camera tensor
`x`, define the exact discrete fiber

\[
\mathcal F_x=\{\delta\in\mathbb Z^n:
  0\le x+\delta\le255,
  R_{pose}(x+\delta)=R_{pose}(x)\ \text{bit-for-bit}\}.
\]

The local Jacobian kernel `ker J_R(x)` is a useful proposal space, not the authority surface. Resize,
float32 rounding, uint8 boundaries, clipping, and later receiver operations make `F_x` a
base-dependent discrete set. It need not be a group, module, vector space, or additive lattice.

The target search problem is therefore

\[
\min_{\delta\in\mathcal F_x\cap\mathcal A}
  \left[
    100\,\Delta d_{seg}(\delta)
    +\sqrt{10(d_{pose}+\Delta d_{pose}(\delta))}-\sqrt{10d_{pose}}
    +\frac{25\,\Delta B(\delta)}{37{,}545{,}489}
  \right],
\]

where `A` is the legal, compiler-reachable mutation set. Exact-D is valuable only when it lowers the
complete objective after the real archive compiler. Pose-input equality is a sufficient local safety
screen, not the final admission predicate.

### 3.2 Primitive integer color kernel

Under the ideal decimal luma relation, a color perturbation `d=(dR,dG,dB)` preserves luma when

\[
299d_R+587d_G+114d_B=0.
\]

Two integer solutions are

\[
v_1=(15,-9,7),\qquad v_2=(26,-8,-27).
\]

Their cross product is

\[
v_1\times v_2=(299,587,114),
\]

so they form a primitive rank-2 basis of the integer kernel. Exhaustive enumeration over all integer
triples in three centered boxes gives:

| coefficient radius `b` | nonzero kernel vectors with `||v||_inf <= b` | primitive independent pairs |
|---:|---:|---:|
| 15 | 2 | 0 |
| 26 | 2 | 0 |
| 27 | 4 | 4 |

Thus 27 is the minimal maximum coefficient for a primitive two-vector basis under this ideal
equation. This is a finite exhaustive proof for the ideal integer equation; it is not a proof of
bit-exactness in the implemented float receiver.

### 3.3 Primitive spatial lattice and the Haar index defect

For one bilinear four-tap support, constant-color offsets preserve the spatial average when the
four coefficients sum to zero. A primitive integer basis is

\[
s_1=e_1-e_4,\quad s_2=e_2-e_4,\quad s_3=e_3-e_4.
\]

The commonly used patterns

\[
h_x=(1,-1,1,-1),\quad
h_y=(1,1,-1,-1),\quad
h_{xy}=(1,-1,-1,1)
\]

have Smith normal form `diag(1,2,2)` relative to the primitive zero-sum lattice. Their determinant
has absolute value four, so integer Haar coefficients cover one of four spatial cosets. Tensoring
with two primitive color directions gives an index

\[
4^2=16
\]

in the ideal rank-6 spatial-color lattice. A primitive codec can distinguish those 16 cosets; an
integer Haar-only codec requires a residue channel or leaves reachable atoms unused.

The information ceiling is `log2(16)=4` raw residue bits per active block. If all 49,152 scorer
blocks were active, the ceiling would be 196,608 bits = 24,576 raw bytes. This is deliberately not
called a saving: activity, symbol distribution, parser overhead, entropy interactions, and exact
receiver survival remain unmeasured.

### 3.4 Resize polyphase structure

For the implemented `874x1164 -> 384x512`, `align_corners=False` bilinear resize:

- the exact rational weight grid has common denominator 98,304;
- the vertical phase period is 192 and horizontal period is 128;
- there are `192*128 = 24,576` polyphase classes;
- all 196,608 scorer pixels have four-tap numerator gcd either 1 or 3;
- 131,072 pixels have gcd 1 and 65,536 have gcd 3; and
- the 49,152 YUV blocks split evenly, 16,384 each, among four-corner gcd patterns
  `(1,3,1,3)`, `(1,1,1,1)`, and `(3,1,3,1)`.

Because each resize stride exceeds two camera pixels, adjacent scorer-pixel four-tap supports are
disjoint in this geometry. Adding one constant RGB offset to all four taps of a single support
bypasses phase weighting because the bilinear weights sum to one. This explains why ideal color-null
directions can create whole-integer scorer-RGB shifts without a phase denominator. Float execution
and camera slack still decide actual exactness.

1. Cacheable singleton exactness is not compositional authority.
2. Greedy waterfilling over independently certified atoms is invalid unless every joint state is

3. The correct combinatorial object is a directed graph whose vertices are exact receiver states and

4. A safe batch is an independent set only when disjoint support and receiver arithmetic jointly

### 5.2 Real-arithmetic quotient

For logits `ell in R^5`, the additive group action

\[
\ell\mapsto\ell+\alpha\mathbf 1
\]

preserves both softmax probabilities and argmax in exact real arithmetic. For an int8 five-vector
`q`, a canonical representative can set the minimum to `-128`:

\[
m=\min_c q_c,\qquad q'_c=q_c-(m+128).
\]

The subtraction is int8-safe **only when computed in widened integer arithmetic**. Because

\[
\min(q')=-128,qquad \max(q')=\max(q)-m-128\le127,
\]

the final result fits int8. Direct int8 subtraction can overflow because `m+128` can be as large as
255.

Encoding each of 97 representatives as a 3-bit argmin plus four int8 values requires

\[
\left\lceil\frac{97(3+4\cdot8)}8\right\rceil=425\ \text{bytes},
\]

an **ideal structural raw reduction of 60 bytes** relative to 485. That arithmetic is derived and
valid. It says nothing yet about parser overhead or compressed archive size.

### 5.3 Why the quotient is not receiver-exact

The actual receiver dequantizes each int8 through float32 before later float64 work. On this packet:

- only 36 of 96 weight columns retain an exactly common dequantized delta;
- 60 of 96 columns have class-dependent spread;
- maximum weight-column spread is `4.76837158203125e-07`; and
- bias-delta spread is `2.9802322387695312e-08`.

Thus the proposed integer normalization does not implement the exact real-arithmetic gauge in the
current finite receiver. Raw output might still round identically for a particular state, but no
complete persisted receiver-output comparison was produced, and the current parser cannot decode the
425-byte form.

An earlier ad-hoc in-memory compressed-block number was not reproducible: candidate bytes, field
order, bit endianness, mapping, script, and SHA were not retained. Fresh plausible reconstructions
range from 50,850 to 50,915 B, with unrelated layouts colliding at the previously discussed number.
Therefore every exact compressed-byte claim for this gauge is **WITHDRAWN**. The only retained
quantitative claim is the 60-byte ideal raw reduction.

### 6.1 Measured region-adjacency graph

For the five semantic classes, the ground-truth RAG has:

\[
K=5,\qquad E=9,\qquad \beta_1=E-K+1=5.
\]

The total measured adjacency count is 1,619,917. Exhaustive enumeration finds 75 spanning trees.
The unique maximum-weight and minimum-weighted-stretch tree contains:

```text
Road -- Lane
Road -- MyCar
Road -- Undrivable
Undrivable -- Movable
```

Its tree-edge mass is 1,521,442, or `93.92098484%` of total adjacency. Its weighted stretch is

The first tree is the default **measured-criterion hypothesis** because it wins both mass and weighted
stretch. The runner-up is the required disambiguation arm because it reduces maximum path length.
Actual archive entropy, receiver locality, class competition, and exact score per byte decide between

### 6.2 Integrable potential coordinates

Choose a semantic root `r` and orient tree edges. With one edge field `u_e` per tree edge, recover
class potentials by path integration:

\[
\ell_c=\ell_r+\sum_{e\in P_T(r,c)}\sigma_{e,c}u_e.
\]

Only `K-1=4` independent edge fields are needed for integrable class differences. Nine unconstrained
edge fields contain five cycle degrees of freedom; moving from 9 to 4 removes `5/9 = 55.6%` of the
coefficient dimension. This is a dimensional statement, not a byte claim.

In graph-Hodge language, an edge signal decomposes into gradient, coexact, and harmonic parts once a
cell complex and inner products are declared. A tree carries only the integrable gradient component.
Cycle chords must be admitted later and charged only if their exact receiver/scorer gain exceeds
their code cost. No coexact claim is legal until explicit two-cells exist; a RAG alone is a graph, not
an arbitrary filled complex.

### 6.3 Minimal topology grammar

Smooth boundary displacement remains in one SDF chart. The minimal discrete handles are:

| event | topological effect | candidate typed atom |
|---|---|---|
| component birth/death | changes `beta0` | bounded disk/ellipse seed or delete |
| bridge/cut | merges/splits components | signed neck insertion/removal |
| fill/puncture | changes `beta1` | bounded hole fill or puncture |
| RAG/junction flip | changes incidence or cyclic order | localized multi-class junction atom |

These correspond to crossing critical faces of the stratified SDF state space. Morse/discrete-Morse
signals propose where a crossing may be valuable; only an exact legal atom with apply/parse/inflate,
topology, Seg, Pose, byte, and rollback receipts may cross R7.

### 6.4 Group, manifold, and Jacobian reading

The continuous SDF parameters form smooth local strata only while quantizer codes, clamp masks,
top-two class ordering, topology signatures, receiver grammar, and manifest remain fixed. Each such
stratum has a `ChartID`. Quantization, argmax, class birth, bridge/cut, junction reorder, or grammar
change crosses a chart face and expires the old Jacobian and costate.

The exact real-logit common-offset action is a gauge group. The implemented quantized receiver does
not currently realize that group action exactly, so quotienting before the receiver is not lawful.
Semantic class permutations are not symmetries because the evaluator fixes class identities. Resize
polyphases form a finite arithmetic partition useful for proposal sharing, not a score symmetry.

## 7. Legal information and rate-distortion lower bounds

For a declared finite legal source family `F`, a decoder fixed independently of the selected source,
and evaluator distortion ball `B_H(y,t)`, any `B`-bit representation must satisfy the packing bound

\[
B\ge \log_2|\mathcal F|
 -\log_2\max_y|B_H(y,t)\cap\mathcal F|.
\]

For a pose manifold `P_pose` under Euclidean pair error, one compatible covering statement is

\[
B\ge\log_2N_{cover}
\left(\mathcal P_{pose},\|\cdot\|_2,\sqrt{mD}\right),
\qquad m=3600.
\]

These bounds become useful only after defining the family, metric, tolerance, decoder class, and
independence assumptions. For one fixed known video and an arbitrarily source-dependent decoder,
source information can be hidden in code; there is no honest absolute Shannon floor.

Separate Seg and Pose lower bounds imply

\[
B\ge\max(B_{seg},B_{pose}),
\]

not `B_seg+B_pose`. Summation requires a product packing or a conditional-independence argument. The
same caution applies to topology, color, and temporal carriers: correlated sufficient statistics may
share bits.

Every proposed free generator or constant must pass a two-world test: hold code fixed, change the
source, and identify every byte/constant that must change. Anything source-derived is counted even if
embedded in syntax. Scorer weights, ground-truth argmax tables, and evaluator-derived output tables
remain forbidden payloads.

The practical lower-bound program is:

1. define nested legal families by grammar and receiver budget;
2. construct packing sets in evaluator quotient space;
3. estimate covering radii with held-out sources/tasks, not the selected video alone;
4. certify decoder independence and count all source-dependent state;
5. compare achieved archives to family-relative bounds; and
6. widen or kill a family only when a certified bound, not one failed optimizer, warrants it.

## 8. Hybrid events, delayed state, and chart-aware costates

### 8.1 State and chart identity

A minimally honest controlled state is

\[
z=(\theta,\bar\theta,o,r,c,q,\mathcal Q,\chi,\rho),
\]

where `theta` is live model state, `bar_theta` EMA state, `o` optimizer state, `r` RNG state, `c`
controller state, `q` quantized/archive state, `Q` the pending asynchronous message queue, `chi` the
topology/quantizer chart, and `rho` the receiver fingerprint. A checkpoint missing any component that
can change the future trajectory is not a complete hybrid-state checkpoint.

Define `ChartID` as a hash of at least:

```text
quantizer codes + clamp mask + top-two class map + topology/RAG/junction signature
+ receiver fingerprint + manifest/grammar identity
```

Derivatives and costates are valid only within the same `ChartID` and measurement regime.

### 8.2 Smooth saltation versus discrete edges

For a smooth transverse event surface `h(z,t)=0` and reset `z+=R(z-)`, the saltation matrix is

\[
\Xi=D R+
\frac{(f^+-D R f^-)n^T}
     {n^Tf^-+\partial_t h},
\qquad n=\nabla_z h.
\]

An adjoint crosses as

\[
\lambda^- = \Xi^T\lambda^+ + \nabla_z c_{event}.
\]

This formula is legal only when differentiability, transversality, reset semantics, and timing are
proved. Quantizer, argmax, topology, and parser events are generally discrete/nontransverse and
should default to explicit graph edges with measured endpoint value, not a pretend continuous
saltation matrix.

For delayed asynchronous sensing, the queue is part of state. Each message must bind source epoch,
source checkpoint hash, payload/hash, schedule/arrival time, uncertainty, worker/runtime identity,
and consumed status. Collision order is deterministic in the forward pass and reversed in the
adjoint. Persisting only `fired_epoch` loses the Markov property.

### 8.3 Full-score costate

The authoritative scalar is

\[
S=100d_{seg}+\sqrt{10d_{pose}}+
  \frac{25B}{37{,}545{,}489}.
\]

Within one smooth chart,

\[
\nabla S=100\nabla d_{seg}
+\frac{5}{\sqrt{10d_{pose}}}\nabla d_{pose}
+\frac{25}{37{,}545{,}489}\nabla B.
\]

At `d_pose=0`, use exact finite differences or a declared limiting treatment rather than dividing by
zero. `B` is the actual compiled archive byte count and is typically discrete; its marginal is an
edge cost, not an ordinary gradient.

Every controller estimate must carry:

```text
coordinate + chart_id + source/target hashes + d_seg contribution + d_pose contribution
+ exact byte contribution + full delta_S + authority axis + uncertainty + status
+ selection/confirmation role + expiry condition
```

The current apparatus still persists `getattr(c,"tier",None)` while the real `CostateEstimate` type
exposes `status`; the existing fake test uses `.tier` and masks the mismatch. Until a real-type
round-trip test passes, stored costate status is untrustworthy. A transition labeled `dS` that records
only `100*delta_d_seg` is not a full-score costate. Rollback and `BEST` selection must compare the
complete score on complete artifacts, never d_seg alone.

### 8.4 Controller admission law

For an action `a` in chart `chi`, define an upper confidence bound on exact score change:

\[
U(a)=\widehat{\Delta S}(a)+r_{uncertainty}(a)+c_{switch}(a).
\]

The controller may propose `a` only if its receiver/compiler edge exists and `U(a)<-delta_admit` on
the declared evidence tier. It may actuate only after a hash-disjoint confirmation receipt. Hard
legality, custody, resume, receiver, and runtime constraints are refusal predicates, not tunable
penalties.

## 9. Anytime-valid selection without corrupting authority

The frozen full-n600 score of one exact deterministic archive is a fixed result and needs no
confidence sequence. Sequential statistics are useful only for randomized early pair sampling,
proxy screening, across-seed uncertainty, or adaptive candidate selection.

The safe protocol is:

1. preregister a random without-replacement pair order and seed;
2. maintain separate time-uniform confidence sequences for d_seg and d_pose;
3. propagate the nonlinear Pose term only after bounding d_pose itself;
4. record exact archive bytes separately because rate is known, not sampled;
5. spend error across adaptive rounds, for example `alpha_j=alpha/2^(j+1)`;
6. keep a hash-disjoint selection ledger and confirmation ledger;
7. never reuse selected pairs as fresh confirmation evidence; and
8. run the complete deterministic n600 exact replay for authority.

The Seg and Pose sequences remain separate because `sqrt(10*d_pose)` couples pair averages
nonlinearly. A delta-method approximation may rank candidates but cannot close the gate unless its
coverage is certified for the observed range. Finite-population without-replacement corrections are
preferred because the 600 pairs are fixed and sampling can be randomized without replacement.

Allowed early outcomes are:

| outcome | meaning |
|---|---|
| `EARLY_FUTILITY` | lower/upper bounds prove the candidate cannot clear the preregistered margin under the remaining population |
| `EARLY_PROMISE` | candidate earns full-n600 confirmation; no score claim yet |
| `CONTINUE_SAMPLING` | interval crosses the decision boundary |
| `HOLDOUT_CONSUMED_BY_SELECTION` | confirmation authority is invalid; allocate a new disjoint confirmation set |
| `FULL_N600_EXACT` | deterministic authority row on exact bytes and declared axis |

## 10. Recursively optimized full-stack design

### 10.1 The optimization problem

“Optimal configuration” is not one guessed flag list. It is a nested constrained program over
representation family `A`, grammar `G`, continuous parameters `theta`, discrete codes `q`, curriculum
policy `pi`, and compiler `C`:

\[
\min_{A,G,\pi,\theta,q}
S\left(E\left(C_G(A,\theta,q)\right)\right)
\]

subject to legality, deterministic decode, resume, runtime, receiver-consumption, archive-custody,
and exact-axis constraints. `E` denotes the frozen evaluator. The outer level chooses the sufficient
statistic and grammar; the middle level learns a receiver-safe continuous state; the inner level
quantizes, entropy-codes, and performs exact discrete polishing.

The recursively repeated unit at every scale is:

```text
state hash -> chart/sensitivity -> candidate edge -> receiver realization
-> exact component delta -> real coder byte delta -> uncertainty/holdout
-> admit, reject, or defer -> durable posterior and checkpoint
```

The same unit applies at pixel, block, boundary segment, class edge, frame pair, stage, seed, vehicle,
and campaign scales. This is the useful meaning of fractal optimization: not ornamental complexity,
but one proof-carrying decision law repeated across resolutions.

### 10.2 Full-stack layers

| layer | owned object | optimality condition |
|---|---|---|
| authority | exact evaluator/receiver/source/runtime hashes | no inferred axis or mutable dependency |
| task geometry | SDF charts, Morse critical faces, RAG/junction state | only task-relevant degrees of freedom persist |
| continuous representation | shared trunk, class potentials, temporal/pair codes | full-rank where needed; no receiver-blind learned state |
| Pose carrier | exact-D or explicitly priced luma/temporal channel | measured Pose value and Seg spill per byte |
| discrete topology | typed birth/bridge/hole/junction handles | exact survival and score value after receiver |
| quantization | chart-aware codes and scales | actual finite receiver behavior, not real-arithmetic fiction |
| entropy grammar | tree potentials, residuals, topology events, codebooks | real encoded bytes and deterministic parse-back |
| controller | hybrid costates, queue, event resets, rollback | complete score and chart-valid evidence |
| curriculum | fixed within-stage losses, event-based transitions | complete stage checkpoint and explicit advance/hold/stop |
| terminal search | compiler-reachable integer neighbor graph | exact full-score improvement per accepted edge |
| evidence | selection/confirmation/full-n600 ledgers | anytime-valid screening, exact final authority |

### 10.3 Knob discipline

Every knob belongs to one of four types:

1. `SEALED_MEASURED`: value already fixed by an authority artifact;
2. `DERIVED`: value follows from dimensions, cadence, runtime, or measured noise;
3. `PROBE_REQUIRED`: two or more defensible values need a preregistered disambiguator; or
4. `INACTIVE`: no receiver/score rationale, so the knob stays off.

There is no `EXPERT_GUESS` type. Continuous hyperparameters are chosen from measured stability and
conditioning. Stage durations derive from event and checkpoint cadence. Loss weights change only at
stage boundaries. Discrete mutation radii derive from camera/code slack and measured receiver
neighborhoods. Entropy choices derive from actual re-encoding. Every added parameter must justify its
charged bytes or serve as source-independent decoder code.

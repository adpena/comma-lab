## MEASUREMENT 1 — Relaxation-plateau criterion backtest (owed-1, A.4 REPAIRED gate)

**Question (A.4 PRIMARY criterion):** `σ_min(J_ξ) ≥ σ_min(∞)·(1−δ)`, σ_min(∞) = fitted asymptote of the
run's OWN σ_min relaxation curve, δ from the fit-residual band. Does the fit converge? δ reasonable?
would-fire honest? Must NOT fire on an unconverged run.

**Method.** Extracted all 31 `jacobian_basin` rows (`median_sigma_min`, ep 4→124) from the STOPPED run
(tau stage `unify_tau`, SIGTERM ep127 — an UNCONVERGED run by construction). Fit
`σ(ep)=s_inf − A·exp(−ep/τ)` via `scipy.optimize.curve_fit` (multi-start over τ₀∈{10…600}, s_inf₀, A₀;
best-SSE). Compared to a constant-model. Computed δ=RMS/s_inf, threshold s_inf·(1−δ), fire-count, hysteresis.
mod32cap has 0 jacobian_basin rows → σ_min unavailable there (documented, not a fit).

**MEASURED numbers (stopped run, n=31):**
- σ_min series: mean **0.0824**, std **0.0175**, min 0.0545, max 0.1205, **CV=std/mean=0.212** (noise is
  21% of signal). Linear trend **RISING +2.13e-4/ep** (drift +0.0264 over the run); first-half mean 0.0753
  vs second-half 0.0891 (+0.0138). This is a NOISY OSCILLATION with a slow upward drift, NOT a monotone
  approach-to-asymptote.
- Best relaxation fit: **s_inf=0.20966 ± 1.867** (rel. uncertainty **891%**), A=0.1414 ± 1.860 (1316%),
  **τ=597.9 ± 8777 ep** (1468%). `scipy` warns *"Covariance of the parameters could not be estimated."*
  Parameters are UNIDENTIFIED. Relaxation beats the constant-model SSE by only **18.9%** (81% of the
  variance is noise-around-a-constant, mis-described by a relaxation curve).
- s_inf (0.210) sits **ABOVE the entire observed range** (max 0.1205) — the rising noise extrapolates a
  far-future asymptote τ≈600 ep never reached in 124 ep.
- δ=RMS/s_inf=**0.075** (looks reasonable but is computed off a garbage s_inf). Threshold s_inf·(1−δ)=**0.194**.
  **Fires on 0/31 rows**; hysteresis-fire (≥3 consecutive ≥ thr, non-decreasing)=**False**.

**Interpretation.** On the "**must NOT fire on an unconverged run**" test the criterion PASSES (0% fire) —
but for the WRONG reason. It does not fire because the fit is DEGENERATE: the rising oscillation pushes s_inf
out of reach, so the threshold sits above all data. This is a fragile accident, not structural convergence
detection. A different run whose noise trends flat or downward would place s_inf INSIDE the data and could
fire spuriously (the δ=0.075 band would then admit ~any near-mean point). The asymptote-fit premise
("does the asymptote fit converge?") is **FALSE** here (891-1468% param CIs; covariance non-estimable).

**VERDICT: FORCES-CHANGE.** The σ_min sensor at k_pairs=32 is too noisy (CV 0.21, oscillation not
relaxation) for a bare exp-asymptote fit. The repaired PRIMARY criterion needs:
(a) a **fit-quality guard** — reject the fit when it does not materially beat a constant-model (here 18.9% is
NOT material) OR when the s_inf CI is huge → then FALL BACK to ship-banked-R1 (never fire on a degenerate
fit, never fire-spuriously on flat noise);
(b) a **robust plateau statistic** instead of the exp-asymptote — e.g. rolling-mean-slope ≈ 0 over a settle
window, or σ_min smoothing / larger k_pairs to cut the 21% noise before fitting.
`# MAGNITUDE_DISMISSAL_OK: 31 measured σ_min rows, scipy fit CI 891%/covariance-non-estimable, SSE-vs-constant +18.9%`.
verdict_scope: FORMULATION (the exp-asymptote formulation of the plateau criterion; a robust-plateau

## MEASUREMENT 3 — amber×Muon double-normalization ($0 static, code-level, owed-3 / A.6 / W-5)

**Question:** is the "per-group-clip × Muon = double-normalization that CRUSHES the seg update" mechanism
mechanically REAL (code-level) or hypothetical?

**Method.** Traced the gradient path in `train_levelset_witness_realized_through_R_mlx.py` L9145-9287 and
read `mlx.optimizers.Muon` source. No training.

**MEASURED (code-level facts):**
1. **Ordering (L9151-9287):** `mean_grads` → global `clip_grad_norm` → **IF amber per-group-clip:** re-clip
   EACH top-level param group to `grad_clip` via `optim.clip_grad_norm(_gsub, grad_clip)` (a scalar factor
   c≤1 per group) → (optional per-param-normalize, only if `--grad-normalize per-param`; amber preset does
   NOT set it) → `opt.update(model, clipped)`. So the per-group-clipped gradient IS what Muon receives.
2. **Muon routing (base L1879 `_is_muon_weight` + L2412-2418):** during the muon stage, `MultiOptimizer`
   routes decoder-hidden weight MATRICES (in_proj/film/hidden `.weight`, ndim≥2) to `optim.Muon`; code-latent,
   biases, out.* → Adam.
3. **MLX Muon `_zeropower_via_newtonschulz5` (decisive):** the FIRST line is
   **`X = X / (mx.linalg.norm(X, keepdims=True) + 1e-7)`** — Frobenius-normalize, DISCARDING all magnitude.
   Newton-Schulz then orthogonalizes (singular values → ≈1). `apply_single` final step:
   **`return parameter - lr * update`** with `lr *= max(1, d_out/d_in)^0.5`. **The Muon update magnitude is
   set ENTIRELY by lr and the shape aspect ratio — INDEPENDENT of the input gradient magnitude.**

**Interpretation.** A scalar per-group clip c≤1 on a Muon param's gradient is **discarded by Newton-Schulz's
Frobenius normalization**. It cannot crush the Muon update magnitude — orthogonalization already throws away
magnitude entirely. The claimed "double-NORMALIZE crushes the seg update" is **mechanically FALSE**. The
per-group clip is a **redundant magnitude no-op** on Muon params.

**What IS real (but different from the claim):**
- (a) **Momentum-direction perturbation:** the Muon momentum buffer `v = μ·v + (1−μ)·(c·g)` mixes
  differently-scaled gradients across fire/no-fire epochs, so the orthogonalized DIRECTION can drift vs
  no-clip. Second-order, direction — NOT a magnitude crush.
- (b) **Observability blind-spot (the genuine S5-N4 kernel):** because the Muon update is magnitude-FLAT
  (`lr·sqrt(scale)` always), any REAL seg suppression (from the GLOBAL clip or the pose-eps floor) is
  INVISIBLE to `gnorm_hijack`/spike-guard on Muon params. Real and sound — but caused by the orthogonalization
  itself, not by the per-group clip.

**VERDICT: FORCES-CHANGE.** (i) The launch-BLOCKING instrumented arm "assert Muon's seg-update magnitude is
not crushed" (A.6/§C owed-3) tests a mechanism that **cannot occur** — it would measure a near-constant and
always "pass," giving false assurance. DEMOTE it from launch-blocking on the crush rationale. (ii) The
Muon-exemption from per-group-clip is still worth building, but as "remove a redundant no-op that injects
momentum-direction noise on Muon params," NOT "prevent a crush." (iii) The REAL amber×Muon telemetry should
measure UPDATE-DIRECTION cosine (clip-on vs clip-off) + per-param effective step, and separately the
observability blind-spot on magnitude-flat Muon updates — not a magnitude-crush assertion.
verdict_scope: FORMULATION (the "double-normalize crush" mechanism + the magnitude-crush test arm; the
exemption itself and the observability concern survive, re-grounded).

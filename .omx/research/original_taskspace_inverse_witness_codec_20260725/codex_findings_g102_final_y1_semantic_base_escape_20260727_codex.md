## The under-our-nose composition error

Two independent mistakes have been conflated.

### 1. Additive repair preserved the wrong rate allocation

G85/G94/G98 treat the 129–134 KB semantic base as immutable and spend only the
remaining headroom on corrections. That is useful causal instrumentation, but
it cannot reclaim bytes whose semantic job is replaced by the new grammar.
G17 and G21 already named this debt:

- `G17_SUBSTITUTIVE_RATE_REALLOCATION_IMPLEMENTATION_OWED`
- `SUBSTITUTIVE_OWNERSHIP_COMPILER_OWED`

At the current batch-16 low-distortion planning coordinate, the entire archive
may be as large as `187,563 B` and still be strictly below `0.172`, or
`154,523 B` and still be strictly below `0.15`. Treating the 133,941-byte
historical-shape base as sunk leaves only `53,622 B` or `20,582 B`.
Replacing the base makes the whole envelope available to the representation
that actually explains the selected solution.

### 2. The first layered run encoded the wrong object

G57 was a real, fresh, full-n600 public experiment, but it encoded resized
source RGB scorer planes at 23 kbps per layer. It did not encode a semantic
program or selected-preimage quotient:

| field | exact G57 result |
|---|---:|
| archive | `182,220 B` |
| `d_seg` | `0.17946555` |
| `d_pose` | `45.10546494` |
| score | `39.30593503092899` |
| Y1 stream | `90,129 B` |
| Y0\|Y1 stream | `90,135 B` |

The public receiver worked; the represented object did not. The decoded
scorer-plane RMSEs were already `8.5172` for Y1 and `8.7835` for Y0 at only
about `0.00611` bits per scorer pixel per layer. V10 then preserved those wrong
planes exactly. This should have been stopped before public evaluation by the
producer-identity boundary.

The correction is not “a better video bitrate.” It is representation of the
evaluator-equivalent **solution** as a semantic/topological program, with
pixels generated by the decoder.

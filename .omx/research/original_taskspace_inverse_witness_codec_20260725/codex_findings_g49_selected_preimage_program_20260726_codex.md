### Coupled decode and resumable population seam

`decode_selected_preimage_pair(program, pair_index, decoder)` returns two
independent, read-only, exact `(384,512,3) uint8` planes. It verifies program,
decoder, semantic, and batch-16 target identities; checks every addressed
counted factor changes receiver behavior; and repeats the decode to reject
nondeterminism.

`iter_selected_preimage_segment(..., pairs_per_segment=120)` exposes an n600
population as five deterministic elementary streams without a dense bank. Each
yield carries local and source pair identity, segment identity, exact program
packet hash, target receipt/bank hashes, and `(Y0,Y1)`. A future launcher can
checkpoint after one segment and resume at the next without decoding prior
pairs.

`BoundV10Factor2SelectedPreimageDecoderV1` composes a freshly bound
`CarrierComposeReceiverV1` with the existing `DisjointResizeOperator`; it can
then realize both scorer planes independently and retain both exact integer
factor-2 proofs.

### Confirmed defects repaired

1. **Stage order was false.** Factor order previously sorted by pair-window
   endpoints before role, so a narrow learned section could execute before a
   broad analytic section despite the claimed
   `semantic -> analytic -> learned` DAG. Canonical compile/application order
   is now role-stage first, then pair range and section ID.
2. **Sparse learned support was falsely treated as dense.** Every pair in a
   learned section envelope was previously considered addressed, so a lawful
   sparse factor failed as receiver-inert outside its support. Learned payloads
   now carry canonical disjoint active pair ranges. Inertness is enforced only
   where the counted factor declares active support.
3. **The executing V10 implementation was not hash-bound.** The packet carried
   `implementation_source_sha256`, but decode checked only a string decoder ID.
   The receiver protocol now exposes its actual implementation source hash and
   decode refuses a mismatch.
4. **The learned plugin was name-only.** A packet-declared plugin contract
   could invoke any callback. Learned payloads now bind both decoder contract
   ID and implementation source SHA; both are checked before execution.
   Double-decode determinism and immutable inputs remain enforced.
5. **Fresh semantic size custody was incomplete.** The concrete bound receiver
   checked semantic archive SHA but not `compiled_semantic_archive_bytes`. It
   now checks both.
6. **Receiver identity mislabeled the called surface.**
   `decode_semantic_base_pair` calls
   `CarrierComposeReceiverV1.render_pairs`, whose source explicitly calls it
   the legacy V9--V13 scorer-grid render. The contract ID now names that exact
   method surface rather than pretending it invokes V15 camera realization.
7. **An analytic atom role was paid but behavior-inert.** The donor
   `BoundaryShearletAtomV1.role` is consumed by the donor carrier *before* its
   shearlet primitive is called; G49 called the primitive directly, where role
   is unread. The wire no longer serializes the inert repeated role token.
8. **Arbitrary atom/section/header caps could suppress factorization.**
   `16,384` atoms, `4,096` sections, and a one-megabyte header were independent
   policy ceilings unrelated to score or parser safety. They are removed.
   Strict caller/compile packet-byte ceilings and the actual uint32 wire length
   now bound parsing. Regression coverage successfully round-trips 16,385
   analytic atoms and 4,097 factor sections.
9. **Dynamic pointer proof state polluted counted receiver bytes.**
   `score_budget_receipt_sha256`, budget rule, and parser ceiling were encoded
   even though the receiver does not consume them. A pointer refresh could
   therefore mutate packet bytes and cost rate without changing function.
   These compile/proof controls are now external to wire identity and dataclass
   equality. A regression proves refreshed budget controls preserve exact
   packet bytes and SHA.
10. **The original tests skipped the load-bearing seams.** They sampled only

## G53 live provenance correction — content identity is not lineage identity

Date: 2026-07-26

This section supersedes every earlier G49/G53 statement that treated a known
archive content SHA as proof of historical byte copying. Root produced a fresh
current-source n600 V15 derivation under a new run ID and typed config, with 38
preserved batch-16 checkpoints, and the result was deterministically
byte-identical to the earlier V15 archive:

- typed config SHA-256:
  `5ab13e5fd1de997d0d4018a0ce94a2e84d74c582db18ad280ffe3b805526dd30`
- current carrier producer source SHA-256:
  `3e1f69bb168da7b42a55ac4ba1a573c0c291a559f6622b40cffa71c219d76d48`

  `759e28332ce1ea2d4cabba731e4b7b2b21c191fef1bd2b104fab18805388d6df`

The old content-SHA blacklist was therefore an invalid provenance test and
could suppress a legitimate deterministic current-source result. A codec must
distinguish:

1. **functional/content identity** — equal receiver-visible bytes;
2. **derivation identity** — which current sources, config, inputs,

3. **physical custody** — which exact bytes occupy the eventual counted outer

Equal leg 1 does not imply copied provenance on leg 2.

### Corrected executable rule

`compile_v9_v10_selected_preimage_program` no longer accepts a caller-created
semantic identity and no longer rejects an output because its SHA is known.
It now reopens:

- canonical compile receipt bytes and their exact SHA;
- exact semantic output bytes/size/SHA;
- current on-disk measurement and carrier producer source bytes;
- typed config canonical hash and run-ID agreement;
- declared V14 archive, V14 receipt, template-bank, and target-cache dependency
  identities;
- exact n600/batch-16 geometry, 38 preserved checkpoints, and batch digest

- full-P camera-byte identity;
- receiver parse/re-encode, all-byte-home, all-role, deterministic-replay, and

The verifier derives a canonical
`tac.v15.semantic_compile_proof_dependency.v1` digest from those facts and
carries only that identity in the inner packet. It refuses source drift,

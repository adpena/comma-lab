# Native source boundary

`corrector.c` is derived from the sealed float64 corrector, with its original
state transitions and ordered products, sums, roots, round-to-even operations,
floor division, recency updates and intermediate float32 narrowing retained.
Comments, unused introspection and repetitive formatting were removed; scratch
allocation uses checked reallocations owned by the same handle. Failed growth
keeps every pointer valid for destruction or retry. A failed live native call
raises instead of retrying a partially advanced state through Python.

The file also implements the existing Lane mixer's fixed-point log2 calculation
and probability normalization using the same sequential float64 operations.
The two native loops are generic receiver algorithms. They use no encoder,
network access, external files, learned table, video-derived per-frame values,
scorer, OpenMP, compiler-specific integer type, or native-host instruction flag.
The counted mixer weights and probability rows are passed from Python; the
dyadic power table is generated by the original generic Python algorithm.

The public shell deletes stale generated libraries before compiling. A missing
or unloadable corrector library emits one clear line and uses the original
Python corrector and mixer. Native corrector initialization checks the complete
23-family Python configuration and arithmetic constants; allocation or platform
sqrt failure selects Python. The source is compiled with `-O2 -std=c11
-ffp-contract=off -fno-fast-math`, plus the shared-library/link flags.

The archive is unchanged. The new port does not invent a compression method or
claim a lower score. Local bit identity is an implementation proof on this host;
target T4 timing and scorer verification remain MAIN-owned.

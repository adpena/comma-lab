## CONCLUSION

**Honest-empty harvest: 0 ADOPT, 0 ADOPT-CLASS, 2 LESSON-ONLY, 4 N-A, and 1
DEAD-BY-RULE.** Chestnut adds real hardware and real large-model deployment machinery, but the
public 0.11.x delta does not expose a new representation, conditional statistic, or receiver
mechanism that attacks this campaign's measured rate floors. The prior-law prediction therefore
survived.

The two lessons are implementation lessons only: out-of-band streaming of a compiled model can cap
peak RAM, and chunked, failure-tolerant materialization can make very large artifacts operational.
Neither compresses our archive. No scorer job, Modal job, model inference, fitting, candidate archive,
or payload encode ran. The exact frontier pointer did not move.

The public release state is internally inconsistent and is kept typed rather than normalized away:

- `RELEASES.md` on public `master` labels **Version 0.11.2 (2026-07-24)** and says **880M
  parameters** `[public-source inspection]`.
- comma.ai's Chestnut post dated **2026-08-12** says a rounded **1B-parameter** model is launching in
  the **upcoming** 0.11.2 release and says it has about **30x** the parameters and **100x** the FLOPs
  of all previous openpilot driving models combined `[public-source inspection]`.
- The official release page still ends at `v0.11.1`; issue `#38468` and the 0.11.2 milestone remain
  open; and the bounded remote-ref census found `v0.11.1` but did not find `v0.11.2` in
  `refs/tags/v0.11.2` `[public-source inspection, 2026-09-01]`.

Accordingly, this memo calls the inspected code the **public-master 0.11.2 surface**, not a
tag-custodied 0.11.2 release. The stable announcement date is 2026-08-12; no release-tag date is
invented.

### Rate format: what is and is not evidenced

The exact reverted object size divided by the changelog's 880M parameter count is
**1.996994569 B/parameter** `[derived from public-source numbers]`, consistent with predominantly
16-bit storage. This is not a tensor-dtype census: graph overhead and non-weight tensors were not
inspected, and the 1.64 GB model was intentionally not downloaded. The sources did not show an int8,
int4, entropy-coded, sparse, or delta-compressed transport format for the large model. They show
`FLOAT16=1` during tinygrad compilation, protocol-5 out-of-band buffers, manifest chunks, and Git
compression disabled for release construction. In other words, comma makes the large model
**buildable, streamable, and recoverable**; it does not demonstrate a byte representation that
addresses our rate door.

## RULE-118 DECODE-SIDE ADJUDICATION

Decode-side Chestnut use is **DEAD-BY-RULE**. `inflate.py` may contain generic deterministic code, but
a public driving model's learned weights remain a large video/domain-derived artifact and must be
charged in `archive.zip`. The source-pinned large object is about **1.757 GB**
`[public-source inspection]`: about **9,763x** the entire **180,002 B** AFR1 archive and about
**12,736x** the **137,986 B** rate-door archive `[derived arithmetic]`. Shipping even a materially
smaller public-master variant would miss the packet budget by orders of magnitude before any
residual. Fetching the model from the network inside inflate would evade custody, introduce an
external mutable learned artifact, and violate the deterministic offline receiver contract. It is
not analogous to e4's pip dependency precedent: generic interpreter/library code can be free;
learned model content is counted. Encode-side use is legally free, but every derived statistic that
the receiver needs is still counted and must beat a named floor. No such statistic was found here.

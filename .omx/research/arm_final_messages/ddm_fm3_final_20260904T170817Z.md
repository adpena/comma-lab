## Three bugs I found in my own work, in the second pass

1. **A perf regression I introduced.** One shared prefilter stem list made the PRIMARY scan pay the
   widening's cost: candidates 160 → 676, verbose gate 0.47 s → 3.83 s, undoing the sp2 ripgrep
   optimisation. Each scope now carries its own stems; a test pins that the primary stems cannot match
   a `.npz` name. Primary restored to 160 / 0.47 s.
2. **A pattern drift.** The census restated the `.npz` pattern instead of importing it, so when I
   re-widened the shipped pattern the census silently measured a different scope. It now imports.
3. **A self-hit.** The A3 scanner counted its own `RETIRED_LITERALS` tuple as live constant sites
   (48 → 40 once excluded). The ruler is not a consumer.

I also fixed a **latent VACUITY==PASS hazard** that predates me: the ripgrep prefilter was a hardcoded
literal independent of the pattern tuple, so a half-added pattern would have matched nothing and the
gate would have reported a clean 0. It is now derived, with a test per scope.

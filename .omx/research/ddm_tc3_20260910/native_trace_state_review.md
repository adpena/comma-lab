## Conclusion and complete persistent state

For this exact ABI1, 23-family implementation, the existing
`ReceiverCheckpoint.arrays()` accessor plus the scalar `have_prev` covers all
probability-affecting native state at a **completed frame boundary**. It
returns 79 arrays: six per-pixel arrays (`prev1`, `prev2`, `run`, `boundary`,
`current`, `known`), three arrays for each of 23 families (`counts`, `hits`,
`phat_q`), the adaptive mixer `weights`, and `miss_counts`, `miss_expect`,
`miss_seen`. No additional persistent numeric learner state was found in the
complete C struct and its mutating routines.

The proposed accessor construction is sound: allocate `ReceiverCheckpoint`
with `__new__`, assign the live `NativeFreeCorrector` to `.corrector`, and
assign `.c` from `ctypes.cast(corrector.handle,
ctypes.POINTER(CorrectorPrefix)).contents`. `arrays()` reads only those two
attributes. It independently compares table views with the exported native
table API. Keep the corrector alive until every view is copied or consumed.

Do not call this partially initialized object's full `save()` or `restore()`
methods: those also require decoder, mixer, root and loaded-state attributes.
Use the array accessor in the trace's own source-bound encoder snapshot path.
Copy every returned view before advancing the live corrector, preserve
`have_prev` separately, and restore by assignment into a fresh constructor's
arrays after exact key-set, dtype and shape validation. Never restore raw
pointer addresses from another process.

## Why omitted fields can be rebuilt

`Family.size`, `count_limit` and `rule` are constructor configuration constants,
not learned state. `plane` is fixed at 384 x 512. A fresh
`NativeFreeCorrector` constructor checks the live Python configuration and
constants against the compiled configuration. Exact source/library hashes
remain necessary: an ABI number and family count alone do not bind semantics.

`capacity` controls scratch allocation and need not match the previous process.
`group_state()` sets `n` and overwrites its probability rows, winner/probability
values, positions, family indices, mixer cells and miss cells for every member
of the next group. `coding_row()` fills all stretches, blended odds, q values
and output scratch before `observe()` consumes them. `observe()` zeroes
`ws_counts` on every call and `ws_gradient` for every family, then overwrites
residual and hit scratch before use. None needs cross-frame preservation.

The Python wrapper's `_serial` is an ownership check for transient
`_NativeGroupState` tokens. It does not affect probabilities. Restarting it
at zero on a fresh corrector object is safe when no old group token is reused.
The generic surprise table is regenerated by native construction and is not
video-derived learned state.

## Required phase and external trace state

Require a live non-null native handle, matching config, ABI1, the 23-family
source layout, plane 196,608, and `group_open == 0` when taking or restoring
the boundary snapshot. **Group closed alone is insufficient:** it is also
true after any intermediate group. The caller must establish that all 190
HPAC groups were observed, then call `corrector.end_frame(final_tokens)` and
the tail mixer's `end_frame` before snapshotting. After a nonempty prefix,
`have_prev` must be one and `prev1` must correspond to the final completed
label plane. Restoring before the next `begin_frame` allows the normal frame
setup to reset current/known and repin boundary as it does in uninterrupted
execution.

The corrector snapshot is only one component of encoder tracing. The existing
trace must also preserve the frame counter, preceding HPAC label plane, all
required TC1 mixer state, both RC64 encoder snapshots, accumulated statistics
and artifact/binding metadata. Do not mix old move39 adaptive state with the
changed move40 field. A current-field full n600 shipped-stream reconstruction
and fresh-process resume control remain the parent's execution gates; this
source review does not substitute for either.
